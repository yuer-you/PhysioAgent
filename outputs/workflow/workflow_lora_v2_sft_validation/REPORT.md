# Workflow LoRA v2 生成式验证报告

## 训练与评测设置

- 基础模型：Qwen2.5-3B-Instruct
- Adapter：`outputs/sft/qwen2.5-3b-workflow-lora-v2/final_adapter`
- 训练集：1800 条，SHA-256 `66da58371d627997e13a1bd37b7c59c7a4f062e2d8d84171a7b1e350125e63a8`
- 验证集：300 条，SHA-256 `aead0dbb6f1069e1ea5f899399578455b6612aaedd955409b9096c0722190a74`
- 最大生成长度：128 token
- 解码：确定性生成
- 指标：严格计划 JSON 与期望步骤完全一致

训练在单张 RTX A4000 上运行 2 epoch，耗时约 32 分 33 秒。最佳 checkpoint 为第二轮的 `checkpoint-226`，验证 loss 为 `0.0134034`。LoRA 配置为 `r=16`、`alpha=32`、`dropout=0.05`，目标模块是 `q_proj` 和 `v_proj`。

## 生成式验证结果

模型自主生成严格正确计划 `275/300`，准确率为 91.7%；有效计划率为 100%。旧工作流开发集仍为 `20/20`，没有观察到原有能力回退。

|---|---:|---:|

| 两步 | 115 / 120 | 95.8% |
| 三步 | 122 / 140 | 87.1% |
| 不加载 | 122 / 122 | 100% |
| 显式列加载 | 84 / 88 | 95.5% |
| 默认列加载 | 69 / 90 | 76.7% |
| 中文 | 139 / 150 | 92.7% |

## 失败分析

25 条失败全部属于参数不匹配，没有非法 JSON、步骤数量错误、工具顺序错误或生成截断。最长输出为 58 token，远低于 128-token 上限。

- 21 条默认加载失败：模型为本应使用 `{}` 的 `load_signal` 虚构了列名；
- 虚构值为 `waveform` 12 次、`ecg` 7 次、`input_field` 1 次、`preset` 1 次；
- 4 条显式加载失败：问题明确给出 `recording`，模型却生成空参数 `{}`；
- 不加载对照全部正确，说明模型没有形成“所有任务都先加载”的捷径。

验证集已经用于模型选择与错误分析，因此不再修改训练数据、adapter 或验证标签并重跑。下一步是在训练前已冻结的 final v3 上，让基础 Qwen 和 Workflow LoRA v2 使用完全相同设置各运行一次。

机器可读结果位于 `lora/summary.json` 和 `lora/results.jsonl`。
