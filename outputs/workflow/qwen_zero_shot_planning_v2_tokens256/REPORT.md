# Qwen 多步规划 v2：256-token 诊断

## 结论

将生成上限从 128 提高到 256 后，结果仍为 **18/20（90%）**，失败案例和模型原文均与第一次 v2 实验相同。因此，“输出因为生成 token 上限而被截断”的假设被排除。

## 证据

- 20 条输出全部为 `reached_max_new_tokens: false`。
- `wf_load_stats_001` 只生成 26 个 token。
- `wf_load_stats_002` 只生成 22 个 token。
- 全部输出最多只使用 43 个 token，远低于 256。
- 两条失败均在最后一个 `}` 前遗漏关闭 `steps` 数组的 `]`。

模型主动结束了生成，而不是被框架强制截断。这说明需要修正的是输出格式遵循能力，而不是显存、上下文长度或生成预算。

## 决策

不继续增加 token 上限，也不自动为模型补上 `]`。下一轮提示词 v3 只加入括号配对和末尾 `]}` 检查，其他变量保持不变，并继续使用严格 JSON 解析。
