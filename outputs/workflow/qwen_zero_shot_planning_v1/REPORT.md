# Qwen 多步规划零样本基线 v1

## 结论

Qwen2.5-3B-Instruct 在 20 条多步规划开发/集成样例上端到端通过 19 条，成功率为 **95%**。
所有“先滤波，再计算心率/检测峰值/计算统计量”的样例均通过，说明基础模型已经能稳定生成项目当前所需的线性工具序列。现阶段没有足够证据支持立刻训练多步 SFT v3。

这组数据用于提示词和工作流接口开发，不是未见最终测试集，因此 95% 不能作为模型最终泛化能力结论。

## 唯一失败案例

案例 `wf_load_stats_002` 要求读取默认信号列后计算统计量。正确做法是省略可选参数：

```json
{"steps":[{"name":"load_signal","arguments":{}},{"name":"calculate_statistics","arguments":{}}]}
```

模型生成了空字符串列名：

```json
{"steps":[{"name":"load_signal","arguments":{"signal_column":""}},{"name":"calculate_statistics","arguments":{}}]}
```

旧版类型校验只检查 `signal_column` 是否为字符串，所以计划被标为合法；执行时才因 CSV 不存在空列名而失败。这是“可选参数语义 + 边界校验”的接口问题，不是工具顺序规划失败。

## 已采取的工程措施

- 在工具 schema 中为 `signal_column` 增加 `minLength: 1`。
- 运行时校验拒绝空字符串和纯空白字符串。
- 增加单元测试，确保错误在计划解析阶段暴露。
- 不修改本次原始结果，不把失败样例事后归一化为成功。

## 下一步

先制作工作流提示词 v2，明确“使用默认列时省略 `signal_column`，任何参数都不能是空字符串”，再使用同一开发集输出到新的目录进行对照。若 v2 达到 20/20，再扩展一批更难的组合、改写和无效请求样例；只有当稳定暴露出基础模型无法通过提示词解决的错误模式时，才构造多步 SFT 数据。
