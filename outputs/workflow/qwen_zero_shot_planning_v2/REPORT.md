# Qwen 多步规划提示词 v2

## 结论

提示词 v2 在同一组 20 条开发/集成样例上端到端通过 **18/20（90%）**，低于 v1 的 19/20（95%），因此不能把 v2 直接宣布为改进版本。

不过，v2 已经纠正 v1 的目标语义错误：`wf_load_stats_002` 不再生成空的 `signal_column`，而是正确生成 `arguments: {}`。该案例和另一个读取列案例最终失败，是因为模型都用 `}` 结束了顶层对象，却遗漏了关闭 `steps` 数组所需的 `]`。

## v1/v2 对照

| 版本 | 合法计划 | 计划严格匹配 | 端到端成功 | 失败案例 |
|---|---:|---:|---:|---|
| v1 | 20/20 | 19/20 | 19/20 | `wf_load_stats_002` |
| v2 | 18/20 | 18/20 | 18/20 | `wf_load_stats_001`、`wf_load_stats_002` |

其他四个类别在两个版本中都全部通过；回归只出现在较长的 `load_signal -> calculate_statistics` 输出。

## 失败内容

v2 对默认列生成的语义已经正确：

```json
{"steps":[{"name":"load_signal","arguments":{}},{"name":"calculate_statistics","arguments":{}}}
```

这段输出在最后一个 `}` 前缺少 `]`，因此严格 JSON 解析器正确地拒绝了它。项目不会自动补全括号，因为自动修复会掩盖模型输出协议错误。

## 下一步实验

当前 `QwenAgent` 的生成上限是 128 token。两个失败都表现为尾部不完整，所以先保持提示词 v2 和评测集不变，只把生成上限提高到 256，并记录每条输出的实际 token 数以及是否触及上限。新结果必须保存到独立目录，不能覆盖本报告对应的 90% 结果。

256-token 实验仍为 18/20。两条失败分别只生成 26 和 22 个 token，所有 20 条样例的 `reached_max_new_tokens` 都是 `false`，因此已经排除生成预算不足。下一步使用提示词 v3 明确要求关闭 `steps` 数组；若仍失败，再考虑结构化解码。
