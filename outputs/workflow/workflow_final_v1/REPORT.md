# 多步工作流冻结最终测试 v1

## 最终结论

固定的 Qwen2.5-3B-Instruct、工作流提示词 v2 和 128-token 生成配置，在 30 条冻结未见问题上取得：

- 严格合法计划：25/30（83.3%）
- 计划严格匹配：18/30（60.0%）
- 严格端到端成功：18/30（60.0%）
- 保守恢复后工程成功：19/30（63.3%）

该结果明显低于预先设定的“严格成功率至少 90%、恢复后至少 95%”标准。基础模型的多步规划能力尚不足，下一阶段应构造独立的多步 SFT 训练数据，而不是继续修改提示词或扩大格式恢复范围。

## 按任务类别

| 类别 | 严格成功 |
|---|---:|
| `filter_then_heart_rate` | 4/4 |
| `filter_then_peaks` | 3/4 |
| `filter_then_statistics` | 3/4 |
| `load_then_statistics` | 2/4 |
| `load_filter_heart_rate` | 1/4 |
| `load_filter_statistics` | 1/4 |
| `single_step` | 4/6 |

按步骤数统计：单步 4/6（66.7%），两步 12/16（75.0%），三步 2/8（25.0%）。最明显的能力缺口是包含显式 `load_signal` 的三步计划。

## 12 条严格失败的类型

- 遗漏用户明确要求的 `load_signal` 步骤：4 条。
- 为默认列生成空字符串：2 条。
- 把普通 ECG/波形描述误当成列名 `ecg`：2 条。
- 为 `load_signal` 创造禁止参数 `signal_profile`：1 条。
- 创造不存在的工具 `calculate_duration`：1 条。
- 将“5 至 16 Hz”错误抽取为 `3 至 16 Hz`：1 条。
- 唯一可保守恢复的缺失 `steps` 数组右括号：1 条。

只有最后一条属于恢复器的明确职责，其余 11 条涉及工具选择、步骤完整性或参数语义，不能通过自动补文本安全修复。

## 为什么开发集成绩不能代表最终能力

20 条开发集已经被用于 v1-v3 提示词迭代，v2 加恢复层在开发集上达到 20/20；冻结的 30 条新问题只有 19/30。这一差距说明开发集成绩存在明显适配效应，也验证了单独冻结测试集的必要性。

本测试复用已有 ECG 文件，因此主要衡量未见语言问题的规划泛化；它不是新的未见生理信号测试。所有原始输出、严格错误和恢复记录都已保留。

## 冻结政策

从本结果开始，不得修改 `workflow_final_cases_v1.jsonl`、期望计划、提示词 v2 或恢复规则后重跑并覆盖本成绩。该测试集也不得进入 SFT 训练数据。

后续多步 SFT 应使用独立模板和问题生成训练/验证集。训练完成后，本 v1 测试最多用于一次模型对比；若根据其失败继续开发，则必须另建 v2 冻结测试集进行最终验收。
