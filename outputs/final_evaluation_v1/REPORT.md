## 总体结果

| 配置 | 合法调用 | 工具名正确 | 请求参数正确 | 多余参数 | 完全匹配 |
|---|---:|---:|---:|---:|---:|
| 原始 Qwen + Prompt v4 | 97% | 96% | 95% | 6% | 90% |
| LoRA v1 + 简洁 prompt | 92% | 92% | 80% | 0% | 80% |
| **LoRA v2 + 简洁 prompt** | **96%** | **96%** | **95%** | **0%** | **95%** |

LoRA v2 比 Prompt v4 的完全匹配率高 5 个百分点，并把多余参数样本从 6 条降到 0 条；
比 LoRA v1 高 15 个百分点。这说明明确参数签名、自然语言参数表达和无参数约束的数据增强是
有效的，而第一版较窄的模板数据泛化不足。

## 成对比较与不确定性

同一批 100 条问题上的成对结果：

- v2 与 Prompt v4：85 条都正确，10 条仅 v2 正确，5 条仅 Prompt v4 正确；精确 McNemar
  检验 `p≈0.302`。5 个百分点的净提升在这 100 条测试上尚不足以证明统计显著。
- v2 与 v1：78 条都正确，17 条仅 v2 正确，2 条仅 v1 正确，3 条都错误；精确 McNemar
  检验 `p≈0.00073`。
- v2 的 95% Wilson 区间约为 88.8%–97.8%；Prompt v4 的区间约为 82.6%–94.5%。

因此可以报告“本测试集上从 90% 提升到 95%”，但不能把它表述成已经证明对所有真实问题
稳定提升 5%。

## LoRA v2 的五个错误

1. 默认列读取时输出 `signal_column: 0`，参数类型错误。
2. 中文突出度峰检测创造了不存在的 `calculate_peaks`。
3. 英文突出度峰检测创造了不存在的 `discard_peaks`。
4. `750 milliseconds` 没有换算为 `0.75 seconds`。
5. “先过滤低突出度峰，再计算心率”输出两个 JSON 调用，而协议只允许一个最终工具调用。

这些错误分别属于默认参数表示、工具白名单稳定性、单位换算和复合意图。由于测试已经解封，
它们只用于报告，不能再加入当前模型的训练或提示词。若未来开发 v3，必须先建立新的、未见过的
`final_cases_v2`。

## 结论与下一阶段

当前文本工具调用模型固定为 LoRA v2。它以简洁 prompt 达到 95/100，超过长 Prompt v4 的
90/100，并彻底消除多余参数。下一阶段不再围绕本测试集调 SFT，而应转向：

1. 将 LoRA v2 接入实际 Agent loop；
2. 引入真实或公开生理信号，验证工具数值输出；
3. 建立端到端问题 → 工具调用 → 工具结果 → 最终回答评测；
4. 将文本路由准确率与信号算法正确性分开报告。

本项目仍是研究与软件演示，不用于临床诊断或治疗。
